# Chiang Rai FloodOps

ระบบติดตามอุปกรณ์ป้องกันและบรรเทาอุทกภัยขององค์กรปกครองส่วนท้องถิ่น จังหวัดเชียงราย พัฒนาเป็นเว็บไซต์แบบ Static SPA เพื่อเผยแพร่ผ่าน GitHub Pages และใช้ Supabase สำหรับ Authentication, PostgreSQL และ Row Level Security (RLS)

## ข้อมูลในเวอร์ชัน 3

เวอร์ชันนี้ใช้ฐานข้อมูลจริงจากไฟล์ `ระบบติดตามอุปกรณ์ป้องกันน้ำท่วม (1).csv` จำนวน 613 รายการ ครอบคลุม 137 หน่วยงาน 19 ประเภทอุปกรณ์ 18 อำเภอ และ 7 บริเวณลุ่มน้ำ

## ฟังก์ชันที่มีในเวอร์ชันนี้

- แดชบอร์ดสรุปจำนวน ประเภท และสถานะอุปกรณ์
- แผนที่ Leaflet พร้อมกลุ่ม Marker และขอบเขตจังหวัดเชียงราย
- ค้นหาอุปกรณ์ใกล้จุดที่คลิกหรือพิกัด GPS ตามรัศมี
- ค้นหาและกรองตามประเภท สถานะ หน่วยงาน และอำเภอ
- เพิ่ม แก้ไข และลบทะเบียนอุปกรณ์
- จัดการหน่วยงานและกำหนดสิทธิ์บัญชีผู้ใช้
- เจ้าหน้าที่ อปท. แก้ไขได้เฉพาะข้อมูลของหน่วยงานตนเองด้วย Supabase RLS
- โหมดสาธิตด้วย Local Storage สำหรับเปิดทดสอบก่อนเชื่อมฐานข้อมูล

## 1. ตั้งค่า Supabase

1. สร้างโครงการใหม่ที่ Supabase
2. เปิด SQL Editor แล้วรันไฟล์ `supabase/schema.sql` ทั้งไฟล์
3. รันไฟล์ `supabase/seed_data.sql` เพื่อเพิ่ม 137 หน่วยงาน 19 ประเภท และอุปกรณ์ 613 รายการ
4. ตรวจสอบด้วย `select count(*) from public.equipment;` ผลลัพธ์ต้องเป็น 613
5. ไปที่ Authentication > Users แล้วสร้างบัญชีผู้ดูแลระบบคนแรก
6. กลับไป SQL Editor และรันคำสั่งท้ายไฟล์ `schema.sql` โดยเปลี่ยนอีเมลให้ตรงกับบัญชีจริง
7. คัดลอก Project URL และ anon/public key จาก Project Settings > API
8. แก้ไฟล์ `js/config.js`

```js
export const APP_CONFIG = {
  supabaseUrl: 'https://YOUR_PROJECT.supabase.co',
  supabaseAnonKey: 'YOUR_ANON_KEY',
  demoMode: false,
  // ...
};
```

ใส่ได้เฉพาะ `anon key` เท่านั้น ห้ามใส่ `service_role key` ในเว็บไซต์หรือ GitHub

## 2. ทดสอบบนเครื่อง

เว็บไซต์ต้องเปิดผ่าน HTTP server ไม่ควรดับเบิลคลิก `index.html` โดยตรง

```bash
python -m http.server 8080
```

จากนั้นเปิด `http://localhost:8080`

## 3. เผยแพร่ผ่าน GitHub Pages

1. สร้าง GitHub Repository และอัปโหลดทุกไฟล์ในโฟลเดอร์นี้ไว้ที่รากของ Repository
2. เปิด Settings > Pages
3. เลือก Deploy from a branch
4. เลือก branch `main` และโฟลเดอร์ `/ (root)`
5. บันทึกและรอ GitHub สร้าง URL

Supabase Authentication > URL Configuration ต้องเพิ่ม URL ของ GitHub Pages ใน Site URL และ Redirect URLs ด้วย

## บทบาทผู้ใช้

| บทบาท | สิทธิ์ |
|---|---|
| `officer` | อ่านข้อมูลทั้งหมด และจัดการข้อมูลอุปกรณ์เฉพาะ อปท. ตนเอง |
| `provincial_admin` | จัดการอุปกรณ์และหน่วยงานทั้งหมด |
| `super_admin` | สิทธิ์ทั้งหมด รวมถึงกำหนดบทบาทและสังกัดผู้ใช้ |

## หมายเหตุด้านระยะทาง

การค้นหาใกล้จุดบนแผนที่คำนวณระยะทางเส้นตรงบนผิวโลก เหมาะสำหรับการคัดเลือกทรัพยากรเบื้องต้น ไม่ใช่ระยะทางหรือเวลาเดินทางตามโครงข่ายถนน หากต้องการ Routing ต้องเชื่อมบริการเส้นทางเพิ่มเติมในภายหลัง

ไฟล์ `supabase/equipment_source_utf8.csv` เป็นสำเนาข้อมูลต้นทางที่ตัดคอลัมน์ว่างออกและแปลงเป็น UTF-8 สำหรับตรวจสอบย้อนหลัง ไม่จำเป็นต้องนำเข้าอีกหากรัน `seed_data.sql` แล้ว

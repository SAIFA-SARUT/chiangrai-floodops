# PDOSS Disaster Relief Equipment

ระบบติดตามอุปกรณ์ป้องกันและบรรเทาอุทกภัยขององค์กรปกครองส่วนท้องถิ่น จังหวัดเชียงราย พัฒนาเป็นเว็บไซต์แบบ Static SPA เพื่อเผยแพร่ผ่าน GitHub Pages และใช้ Supabase สำหรับ Authentication, PostgreSQL และ Row Level Security (RLS)

## ข้อมูลในเวอร์ชัน 3

เวอร์ชันนี้ใช้ฐานข้อมูลจริงจากไฟล์ `ระบบติดตามอุปกรณ์ป้องกันน้ำท่วม (1).csv` จำนวน 613 รายการ และทะเบียนรหัส อปท. จังหวัดเชียงราย 144 แห่ง ครอบคลุม 19 ประเภทอุปกรณ์ 18 อำเภอ และ 7 บริเวณลุ่มน้ำ

รหัสอุปกรณ์ใช้รูปแบบ `1803-0001` โดย 4 หลักแรกเป็นรหัสย่อจาก 4 หลักท้ายของรหัส อปท. ทางการ และ 4 หลักหลังเป็นเลขลำดับอุปกรณ์ภายในหน่วยงาน ระบบเป็นผู้ออกเลขให้อัตโนมัติและจะไม่นำเลขเก่ากลับมาใช้ ส่วนรหัสเดิม `FP-xxx` ถูกเก็บไว้ใน `legacy_code`

## ฟังก์ชันที่มีในเวอร์ชันนี้

- แดชบอร์ดสรุปจำนวน ประเภท และสถานะอุปกรณ์
- แผนที่ Leaflet พร้อมกลุ่ม Marker และขอบเขตจังหวัดเชียงราย
- สลับพื้นหลังแผนที่ระหว่าง Street Map และ Satellite Map ได้โดยไม่กระทบหมุด การค้นหารัศมี หรือ GPS
- บุคคลทั่วไปเปิดดูแผนที่และค้นหาอุปกรณ์ใกล้จุดเกิดเหตุได้โดยไม่ต้องเข้าสู่ระบบ
- ค้นหาอุปกรณ์ใกล้จุดที่คลิกหรือพิกัด GPS ตามรัศมี
- ค้นหาและกรองตามประเภท สถานะ หน่วยงาน และอำเภอ
- เพิ่ม แก้ไข และลบทะเบียนอุปกรณ์
- นำเข้าและแก้ไขข้อมูลจำนวนมากด้วย Excel พร้อมตรวจสอบทั้งไฟล์ก่อนบันทึก
- ตารางคลังอุปกรณ์แบ่งหน้าละ 20 รายการ โดยการส่งออกยังส่งออกข้อมูลทั้งหมดตามตัวกรอง
- แบรนด์ CRPAO / PDOSS โทนม่วงอมชมพู และตัดปุ่มเพิ่มอุปกรณ์ออกจากแถบด้านบน
- จัดกลุ่มหน่วยงานตามอำเภอ พร้อมค้นหาและกรองรายอำเภอ
- เปิดดูรายละเอียด อปท. สรุปสถานะ ประเภท รายการอุปกรณ์ และเชื่อมไปยังแผนที่ได้
- กราฟประเภทอุปกรณ์แนวนอน แสดงครบทุกประเภท
- ซ่อนแถบหัวด้านบนบนคอมพิวเตอร์ ย้ายวันที่เข้าไปในหัวข้อหน้า และคงแถบเมนูแบบย่อบนโทรศัพท์
- แสดงหมุดศูนย์กลางค้นหารัศมีแยกสีระหว่างจุดที่คลิกกับตำแหน่ง GPS
- ใช้ตรา อบจ.เชียงรายแทนตัวอักษร CRPAO พร้อมโลโก้ PDOSS ในหน้าเข้าสู่ระบบและการ์ดผู้บริหารบนแถบเมนู
- จัดการหน่วยงานและกำหนดสิทธิ์บัญชีผู้ใช้
- เจ้าหน้าที่ อปท. แก้ไขได้เฉพาะข้อมูลของหน่วยงานตนเองด้วย Supabase RLS
- โหมดสาธิตด้วย Local Storage สำหรับเปิดทดสอบก่อนเชื่อมฐานข้อมูล

## 1. ตั้งค่า Supabase

1. สร้างโครงการใหม่ที่ Supabase
2. เปิด SQL Editor แล้วรันไฟล์ `supabase/schema.sql` ทั้งไฟล์
3. รันไฟล์ `supabase/seed_data.sql` เพื่อเพิ่มทะเบียน อปท. 144 แห่ง อุปกรณ์ 19 ประเภท และข้อมูลอุปกรณ์ 613 รายการ
4. ตรวจสอบด้วย `select count(*) from public.equipment;` ผลลัพธ์ต้องเป็น 613
5. ไปที่ Authentication > Users แล้วสร้างบัญชีผู้ดูแลระบบคนแรก
6. กลับไป SQL Editor และรันคำสั่งท้ายไฟล์ `schema.sql` โดยเปลี่ยนอีเมลให้ตรงกับบัญชีจริง
7. คัดลอก Project URL และ anon/public key จาก Project Settings > API
8. แก้ไฟล์ `js/config.js`

```js
export const APP_CONFIG = {
  supabaseUrl: 'https://YOUR_PROJECT.supabase.co',
  supabaseAnonKey: 'YOUR_ANON_KEY',
  demoMode: false,
  // ...
};
```

ใส่ได้เฉพาะ `anon key` เท่านั้น ห้ามใส่ `service_role key` ในเว็บไซต์หรือ GitHub

## 2. ทดสอบบนเครื่อง

เว็บไซต์ต้องเปิดผ่าน HTTP server ไม่ควรดับเบิลคลิก `index.html` โดยตรง

```bash
python -m http.server 8080
```

จากนั้นเปิด `http://localhost:8080`

## 3. เผยแพร่ผ่าน GitHub Pages

1. สร้าง GitHub Repository และอัปโหลดทุกไฟล์ในโฟลเดอร์นี้ไว้ที่รากของ Repository
2. เปิด Settings > Pages
3. เลือก Deploy from a branch
4. เลือก branch `main` และโฟลเดอร์ `/ (root)`
5. บันทึกและรอ GitHub สร้าง URL

Supabase Authentication > URL Configuration ต้องเพิ่ม URL ของ GitHub Pages ใน Site URL และ Redirect URLs ด้วย

| บทบาท | สิทธิ์ |

| `officer` | อ่านข้อมูลทั้งหมด และจัดการข้อมูลอุปกรณ์เฉพาะ อปท. ตนเอง |

## หมายเหตุด้านระยะทาง

การค้นหาใกล้จุดบนแผนที่คำนวณระยะทางเส้นตรงบนผิวโลก เหมาะสำหรับการคัดเลือกทรัพยากรเบื้องต้น ไม่ใช่ระยะทางหรือเวลาเดินทางตามโครงข่ายถนน หากต้องการ Routing ต้องเชื่อมบริการเส้นทางเพิ่มเติมในภายหลัง

ไฟล์ `supabase/equipment_source_utf8.csv` เป็นสำเนาข้อมูลต้นทางที่ตัดคอลัมน์ว่างออกและแปลงเป็น UTF-8 สำหรับตรวจสอบย้อนหลัง ไม่จำเป็นต้องนำเข้าอีกหากรัน `seed_data.sql` แล้ว

## ปรับฐานข้อมูลเดิมที่ใช้งานอยู่

หากเคยรัน `schema.sql` และ `seed_data.sql` เวอร์ชันก่อนหน้าแล้ว ไม่ต้องลบโครงการหรือข้อมูลเดิม ให้สำรองฐานข้อมูล จากนั้นเปิด Supabase SQL Editor และรัน `supabase/migrate_equipment_codes.sql` เพียงครั้งเดียว ไฟล์นี้จะเพิ่มรหัส อปท. แยกหน่วยงานชื่อซ้ำตามอำเภอ เก็บรหัส `FP-xxx` เดิม และเปลี่ยนรหัสอุปกรณ์เป็นรูปแบบใหม่โดยอัตโนมัติ

จากนั้นรัน `supabase/enable_public_map.sql` เพียงครั้งเดียว เพื่อเปิดข้อมูลแผนที่แบบอ่านอย่างเดียวสำหรับบุคคลทั่วไป โดยข้อมูลบัญชีผู้ใช้ เบอร์ติดต่อ ผู้ประสานงาน หมายเหตุ และประวัติการแก้ไขยังคงเป็นข้อมูลภายใน

หากฐานข้อมูลเดิมยังแสดงไอคอนกล่องเครื่องมือกับรถบางประเภท ให้รัน `supabase/update_equipment_icons.sql` เพียงครั้งเดียว เพื่อกำหนดอีโมจิให้ครบทั้ง 19 ประเภท

หากต้องการใช้ปุ่ม **นำเข้า Excel** ให้รัน `supabase/enable_excel_import.sql` เพียงครั้งเดียว ระบบจะตรวจสิทธิ์ซ้ำที่ฐานข้อมูล เจ้าหน้าที่นำเข้าได้เฉพาะ อปท. ของตนเอง และหากมีแถวใดผิดพลาดจะยกเลิกทั้งชุดโดยไม่บันทึกบางส่วน

ในหน้า **คลังอุปกรณ์** ให้กด **นำเข้า Excel** แล้วดาวน์โหลดไฟล์ตัวอย่างจากหน้าต่างที่เปิดขึ้น การเพิ่มรายการใหม่ให้เว้นคอลัมน์ `รหัสอุปกรณ์` ว่าง ส่วนการแก้ไขให้ระบุรหัสเดิม เช่น `1803-0001` ระบบจะไม่อนุญาตให้เปลี่ยนหน่วยงานเจ้าของผ่านไฟล์ Excel
